Infrastructure Recap for Terraform CI/CD-----------
-Our ADO build pipeline accesses our Azure Storage Account/Container/Blobs to pull in our tfstate files and tfvars blob files.
-The Terraform State file gets created when you run your first Terraform plan/apply which is done by the ADO pipeline anyways.
-Our ADO build pipeline will leverage this injection at runtime with terraform init:
terraform init \
  -backend-config=backend.conf \
  -backend-config="key=$(environment).tfstate"

-Our ADO build pipeline will leverage our backend.tf file and upload the tfstate files as if we did a "terraform init / plan / apply" right from our VSCode terminal.
-We STILL need to use a backend codeblock in our backend.tf file for uploading our tfstate files to our AZ Storage Account.
-We can keep our git-based workflow in VSCode, that does not change.

The Gotcha:
We will manually need to upload our TFVars files to our AZ Storage Account as there is no automated way to do this.
NOTE: We do not want to use any terraform workspace cmds because this interrupts our CI/CD Git flow, and prevents
other contributors (DevOps) from working on the same project easily due to tfstate discrepancies.
